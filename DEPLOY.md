# Как выложить сайт на домен bayern.am

Сайт уже публикуется автоматически: каждый раз, когда изменения попадают на GitHub, обновляется страница https://adamyan23.github.io/Bayern/. Осталось привязать к ней ваш домен. Платить ни за что не нужно, сертификат HTTPS GitHub выпустит сам.

Делается один раз. Между шагами 2 и 3 нужно подождать — обычно 15–60 минут, иногда до суток.

---

## Шаг 1. Прописать домен на GitHub

1. Откройте https://github.com/Adamyan23/Bayern/settings/pages
2. Раздел **Custom domain** → впишите `bayern.am` → **Save**.
3. GitHub напишет «DNS check in progress» — так и должно быть, пока не сделан шаг 2.

При сохранении в репозитории сам появится файл `CNAME` с текстом `bayern.am`. Не удаляйте его.

## Шаг 2. Настроить домен у регистратора

Зайдите в личный кабинет, где вы покупали `bayern.am` (для армянских доменов это обычно abcdomain.am, internet.am или ISOC AM), и откройте **DNS** / **Управление зоной**.

Добавьте **четыре записи A** для самого домена. Везде: тип **A**, имя (Host/Name) — `@` или пустое, TTL — по умолчанию.

| Тип | Имя | Значение |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |

И **одну запись CNAME** для адреса с `www`:

| Тип | Имя | Значение |
|---|---|---|
| CNAME | www | adamyan23.github.io. |

Если в зоне уже есть записи A для `@` (например, от заглушки регистратора) — удалите их, иначе домен будет открывать старую страницу.

Необязательно, но полезно (IPv6) — ещё четыре записи типа **AAAA** для `@`:
`2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`

## Шаг 3. Включить HTTPS

1. Подождите, пока на странице https://github.com/Adamyan23/Bayern/settings/pages появится зелёная галочка **DNS check successful**. Если её долго нет, нажмите **Remove** рядом с доменом, впишите `bayern.am` заново и сохраните.
2. Поставьте галочку **Enforce HTTPS**. Она может быть неактивна ещё около часа, пока выпускается сертификат.
3. Откройте https://bayern.am — должен открыться сайт с замочком в адресной строке.

---

## Что дальше

- **Обновления.** Любые изменения попадают на сайт сами, через 1–2 минуты после отправки на GitHub.
- **Почтовый ящик.** DNS-записи выше отвечают только за сайт. Почта `info@bayern.am` живёт на записях **MX** — их не трогайте, иначе письма перестанут приходить.
- **Адрес без www.** Обе формы работают: `www.bayern.am` перебросит на `bayern.am`.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Открывается страница регистратора | В зоне остались старые записи A для `@` — удалите их |
| «Не защищено» / нет замочка | Сертификат ещё выпускается. Подождите час и включите **Enforce HTTPS** |
| 404 на bayern.am | Проверьте, что в репозитории есть файл `CNAME` с текстом `bayern.am` и что в Settings → Pages источник — ветка `main`, папка `/ (root)` |
| Хочу проверить, дошли ли записи | На https://dnschecker.org введите `bayern.am` и тип **A** — должны быть четыре адреса `185.199.*.153` |

## Другой вариант

Если позже репозиторий захочется сделать приватным (GitHub Pages тогда потребует платный тариф), сайт можно бесплатно публиковать через **Cloudflare Pages** или **Netlify**: подключаете тот же репозиторий, указываете, что собирать ничего не нужно, и добавляете домен там. Скажите — распишу.
